# Контракт сетевого взаимодействия

Базовый префикс: `/api/v1/network`. Все ответы успешных API обёрнуты в
`{"success": true, "data": ...}`. Peer-запросы отправляют `X-API-Key`.

## Node A → Node B

### Получить сведения об узле

`GET /info`

Ответ содержит `node_id`, `network_id`, `genesis_hash`, `block_count`, `height`,
`head_hash` и `valid`. Доступ требует API-ключ.

### Получить блок

`GET /blocks/{hash}`

Возвращает сериализованный блок, если он присутствует в цепочке. Неизвестный хэш
возвращает `404 block_not_found`.

### Передать блок

`POST /blocks`

Тело:

```json
{
  "block": {
    "index": 1,
    "timestamp": 1727184600.0,
    "previous_hash": "<64 lowercase hex characters>",
    "hash": "<64 lowercase hex characters>",
    "transactions": [
      {
        "deal_id": "network-demo-123",
        "status": 4,
        "timestamp": 1727184600.0,
        "file_path": null,
        "file_hash": null,
        "content_hash": "<64 lowercase hex characters>"
      }
    ]
  }
}
```

Успешный ответ (`200`) содержит `accepted`, `node_id`, `index`, `hash`,
`block_count`, `head_hash` и `validation`. Блок появляется в локальной цепочке
получателя только после успешной проверки и сохранения.

## Операции узла-отправителя

- `GET /peers` — опрашивает каждый настроенный адрес и возвращает состояние и
  совместимость peer.
- `GET /peers/{peer_id}/info` — запрашивает информацию заданного известного узла.
- `GET /peers/{peer_id}/blocks/{hash}` — запрашивает и возвращает блок с другого узла.
- `POST /peers/{peer_id}/blocks/{hash}/send` — берёт блок из локальной цепочки,
  проверяет сеть/genesis получателя и отправляет его.
- `POST /peers/{peer_id}/invalid-block-demo` — только в `APP_ENV=dev` или `demo`;
  отправляет заведомо некорректный блок и возвращает фактическое доказательство отказа.

## Ошибки

Ошибки FastAPI используют стандартный `detail`; для сетевых ошибок он содержит
`code`, `message` и, при необходимости, `details`.

- `401` — отсутствующий или неверный `X-API-Key`.
- `404 unknown_peer` — peer отсутствует в `PEERS_JSON`.
- `404 block_not_found` — хэш не найден на запрошенном узле.
- `409 incompatible_peer` — удалённый `node_id`, `network_id` или genesis-хэш
  не совпадает с ожидаемым.
- `422 invalid_block` — некорректная структура, индекс, ссылка на предыдущий блок,
  хэш блока или хэш записи. Массив `errors` содержит тип, сообщение, индекс и
  ожидаемое/фактическое значение.
- `422 block_already_present` — повторная передача уже сохранённого блока.
- `422` валидации запроса — некорректная структура JSON-блока или поля вне ограничений схемы.
- `503 peer_unreachable` / `504 peer_timeout` — удалённый узел недоступен или не ответил.

Автоматическая синхронизация намеренно не входит в контракт. Получатель не принимает
блок, если он не является следующим блоком его локальной истории.
