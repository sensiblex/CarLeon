# Сетевые тестовые сценарии

## Положительные

1. Два экземпляра с разными файлами создают одинаковый genesis-хэш.
2. Node A опрашивает настроенный Node B; ответ содержит идентификатор, сеть,
   высоту, количество блоков и вершину.
3. Node A создаёт блок с записью и передаёт его Node B.
4. Node B проверяет блок, добавляет его и возвращает совпадающие индекс и хэш.
5. Node A запрашивает блок обратно у Node B; полученный хэш и транзакция совпадают
   с отправленными данными.
6. Оба независимых файла содержат принятый блок после обмена.
7. UI показывает реальные ответы и вершины обеих нод.

## Негативные

1. Запрос `/info` и отправка блока без API-ключа возвращают `401`.
2. Неизвестный `peer_id` возвращает `404 unknown_peer`.
3. Peer с иным `network_id` или genesis-хэшем помечается несовместимым; передача
   ему блока прекращается.
4. Изменение транзакции без пересчёта хэшей отклоняется как `422 invalid_block`.
5. Неправильный `previous_hash` или индекс отклоняется до записи в файл.
6. Повторная передача блока отклоняется и не добавляет дубликат.
7. Блок с некорректной структурой отклоняется схемой запроса.
8. Недоступный адрес возвращает `peer_unreachable`; превышение таймаута —
   `peer_timeout`.
9. Демонстрационный повреждённый блок не меняет количество блоков и хэш вершины
   принимающей ноды.
